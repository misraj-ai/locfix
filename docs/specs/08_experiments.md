## 2. Main claim and how it is tested

**Claim:** training the localizer with fixer-likelihood weights (S3) improves end-to-end resolve
rate over the strong separate-training baseline (S2b), at equal data and compute.
**Test:** `S3-*-best` vs `S2b-*` on `heldout` (+ `dev`), paired McNemar, two seeds, both models.
Supporting evidence: the signal test; localization diagnostics; requests per issue; |z| tokens.

## 3. Paper tables and figures (generated by `locfix report`)

1. **Main table:** resolve rate (95% CI) on dev and heldout for S0, S1, S2a, S2b, S3-best, S4-best;
   E4B and 31B columns.
2. **EM ablation table (E4B):** hard / soft / soft-weighted / no-requests / LOO, rounds 1–2.
3. **Signal test:** resolve with top-weighted z vs teacher-label z, discordant counts.
4. **Localization diagnostics:** file/function recall and precision vs L_edit, |z| tokens,
   requests per issue, per round; correlation between w and actual resolve.
5. **Behaviour under the budget:** distribution of counted tool calls and time per task, timeout
   rate, `submit_patch` rate (relevant to the 5-minute cap).
6. **Data table:** records per source and stage after each filter, tokens, cleaning-v2 drops.
7. **Compute table:** GPU-hours per stage (from run logs, not estimates).

## 4. Reproducibility package

- `README.md` "Reproducing the paper": exact commands per row of the main table.
- Released configs for every run in the tables; seeds; version pins; `run_meta.json` files.
- Data release is a separate decision (teacher trajectories from Kimi K3 via OpenRouter: check the
  provider's terms before publishing them); the code must run on any data in the documented format.
